# Folder Structure for Base AI Python Project

Below is the folder structure for the FastAPI application, organized for clarity and modularity.

## High-Level Structure

```
root-folder/
├── alembic/               # Alembic database migration scripts and environment
├── app/                   # Main application source code
│   ├── agents/            # (Potentially) Agent-related logic
│   ├── api/               # API specific code (endpoints, main app instance)
│   ├── cli/               # (Potentially) Command-line interface logic
│   ├── core/              # Core business logic, database, utilities, modules
│   ├── llms/              # (Potentially) LLM interaction logic
│   ├── tools/             # (Potentially) Tool definitions for agents/LLMs
│   └── __init__.py
├── docs/                  # Project documentation (overview.md, structure.md, status.md)
├── tests/                 # (Recommended) Unit and integration tests
├── .env                   # Environment variables (gitignored)
├── .env.example           # Example environment variables
├── .gitignore             # Git ignore configuration
├── .pre-commit-config.yaml # Pre-commit hook configuration
├── .python-version        # Specifies Python version (e.g., for pyenv)
├── alembic.ini            # Alembic configuration file
├── pyproject.toml         # Project metadata and dependencies (for uv/pip)
├── README.md              # Project README
└── uv.lock                # uv lock file
```

## Detailed Structure Explanation

### Root Directory

-   **`alembic/`**: Contains Alembic configuration (`env.py`) and generated database migration scripts (`versions/`). Manages database schema changes.
-   **`app/`**: The primary Python package containing all application source code.
-   **`docs/`**: Markdown files providing documentation about the project (overview, structure, status).
-   **`tests/`**: (Recommended location) Contains test suites (`pytest`).
-   **`.env`**: Stores sensitive configuration and environment variables (e.g., database URL, secret keys). Not committed to Git.
-   **`.env.example`**: Template file showing required environment variables.
-   **`.gitignore`**: Specifies intentionally untracked files that Git should ignore.
-   **`.pre-commit-config.yaml`**: Configuration for pre-commit hooks (e.g., for linting/formatting).
-   **`.python-version`**: Used by tools like `pyenv` to manage the Python version for the project.
-   **`alembic.ini`**: Main configuration file for Alembic.
-   **`pyproject.toml`**: Standard Python project definition file, used by `uv` (and modern `pip`/`build`) for defining dependencies and build system requirements.
-   **`README.md`**: Introductory documentation for the project.
-   **`uv.lock`**: Lock file generated by `uv` to ensure deterministic dependency installation.

### `app/` Directory - Application Core

-   **`api/`**: Handles the web API layer.
    -   **`main.py`**: Creates the main FastAPI application instance (`app`), sets up lifespan events (e.g., engine disposal), configures exception handlers, and mounts API routers.
    -   **`v1/`**: Represents version 1 of the API.
        -   **`endpoints.py`**: Aggregates and includes routers from different API modules (like public, internal, auth).
        -   **`public/`**: Contains publicly accessible API endpoints.
            -   `endpoints/`: Routers for specific public resources (e.g., `users.py`).
            -   `schemas/`: Pydantic schemas specific to public endpoints (requests/responses).
        -   **`auth/`**: Contains authentication-related endpoints and schemas.
            -   `endpoints.py`: Login, potentially refresh/logout endpoints.
            -   `schemas.py`: Token schemas (`Token`, `TokenData`).
        -   **`internal/`, `chat/`, `agents/`**: Other potential API modules grouped by functionality.
    -   **`middlewares/`**: (Optional) Custom FastAPI middleware.
    -   **`utils/`**: (Optional) Utility functions specific to the API layer.
-   **`core/`**: Contains the core business logic, database interactions, and shared components, independent of the API layer.
    -   **`config.py`**: Defines Pydantic `Settings` model to load configuration from environment variables (`.env`).
    -   **`db/`**: Database specific setup.
        -   `database.py`: Initializes the SQLAlchemy async engine (`engine`), session maker (`AsyncSessionLocal`), and declarative base (`Base`).
        -   `dependencies.py`: Defines FastAPI dependencies, notably `get_db` for session management per request.
    -   **`modules/`**: Contains distinct business logic modules.
        -   `users/`: Handles user-related logic.
            -   `models/user.py`: SQLAlchemy `User` model.
            -   `services.py`: Business logic functions (CRUD operations, authentication logic) interacting with the database.
        -   `auth/`:
            -   `auth_securities.py`: Security-related functions (password hashing, JWT creation/decoding).
            -   `auth_dependencies.py`: Authentication dependencies (`jwt_auth`, `refresh_token_auth` using `HTTPBearer`).
    -   **`common/`**: (Optional) Shared components like custom exceptions, enums, etc.
    -   **`utils/`**: (Optional) General utility functions used across the core.
-   **`agents/**, **cli/**, **llms/**, **tools/****: These directories suggest modules related to AI agents, command-line tasks, Large Language Model interactions, and associated tools. Their specific structure would depend on the implementation.

-   **`llms/`**: Logic related to Large Language Model interactions.
    - `clients/`: Contains specific clients or wrappers for different LLM providers/APIs.
    - `prompts/`: Stores prompt templates or prompt management logic.
    - `__init__.py`

-   **`agents/`**: Implementation of autonomous agents.
    - `memory/`: Components related to agent memory (e.g., chat history, state management).
    - `base_agent.py`: Base class or core logic for agents.
    - `llm_agent.py`: Specific agent implementation utilizing LLMs.
    - `__init__.py`

-   **`tools/`**: Definitions of tools that agents or LLMs can utilize.
    - `items/`: Contains implementations of specific tools.
    - `base_tool.py`: Base class or interface for tools.
    - `schemas.py`: Pydantic schemas related to tool inputs/outputs.
    - `__init__.py`

-   **`cli/`**: (Potentially) Command-line interface logic (Structure not detailed).

This structure promotes separation of concerns, making the application easier to understand, maintain, and test.
